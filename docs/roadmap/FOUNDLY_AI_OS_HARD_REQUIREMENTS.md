**DISCOVER → OBSERVE → BENCHMARK → LEARN → GAP → DESIGN → BUILD → TEST → RED-TEAM → COMPARE → DEPLOY → MEASURE → LEARN AGAIN**

This engine applies to every major capability.

ZERO must continuously maintain:
- current strongest relevant competitors;
- current strongest models/providers;
- capability ledgers;
- quality dimensions;
- cost/latency dimensions;
- reliability dimensions;
- accessibility;
- security/privacy;
- user effort;
- business-outcome evidence;
- release dates and source freshness;
- uncertainty and confidence;
- observed customer outcomes where authorized.

Foundly must not hard-code one competitor or model as permanently strongest.

Competitor and model benchmarks must be refreshed at execution time.

Public websites and documentation may be analyzed only through legitimate public access. Foundly must respect access controls, robots restrictions, terms, privacy and copyright. It may abstract patterns and capabilities, but must not copy protected code/content or bypass access restrictions.

Continuous learning means governed memory, evaluations, benchmark data, successful patterns, failed patterns and outcome evidence. It does **not** mean uncontrolled self-modification of foundation-model weights or production code.

Any self-improvement must follow normal:
- permissions;
- tests;
- review;
- CI;
- release;
- rollback;
- audit;
- budget controls.

# 3. GLOBAL BEST-IN-CLASS ACCEPTANCE LAW

For every major Foundly capability:

1. Discover the strongest current relevant specialist competitors.
2. Build a capability ledger.
3. Define measurable benchmark scenarios.
4. Establish a reproducible baseline.
5. Implement or improve Foundly.
6. Test on identical or equivalent tasks.
7. Red-team failures and edge cases.
8. Compare quality, speed, cost, reliability and user effort.
9. Do not mark PASS until the stated acceptance bar is evidence-backed.

Minimum target:
**PARITY WITH CURRENT BEST-IN-CLASS ON CORE USER FLOWS.**

Strategic target:
**DEMONSTRABLE SUPERIORITY ON FOUNDLY’S DIFFERENTIATORS WHERE TECHNICALLY FEASIBLE.**

Foundly’s intended differentiators include:
- ZERO-driven natural-language operation;
- cross-module business context;
- source provenance;
- permission-aware execution;
- recovery/idempotency;
- lower user effort;
- faster end-to-end execution;
- measurable business outcomes;
- multi-model routing;
- continuous learning;
- lower compute/cost where quality is maintained;
- one unified system instead of isolated point tools.

No absolute “best in the world” claim may be made without current evidence.
