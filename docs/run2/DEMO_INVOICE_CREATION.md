# Reviewed invoice creation in both priority demos

The Finance page can now create manual native sales and purchase invoice drafts through the existing Finance contract or structured ZERO. Creation is a separate expandable panel with a paged native legal-entity selector, explicit invoice type, number, invoice/supply/due dates, supplier and customer details, and one to fifty editable invoice lines. Each line requires a description, positive decimal quantity, exact unit price and explicitly entered tax rate. No tax rate or missing registration data is invented. An explicit button copies the selected entity's available own-business details into the appropriate party fields.

Preparation uses native calculations and shows the parties, dates, document number, each line's quantity, unit price, net, tax and gross, and the native total. Editing any source field or line invalidates the preparation and clears confirmation. The separate reason and checkbox confirm the exact source-bound payload. Creation only records a draft; purchase approval, posting and internal payment remain separate actions with their original permissions.

The normal encrypted server store retains the exact confirmation under its current owner before execution. A physically lost response is recovered after restart without creating a second invoice. Original draft and current invoice remain distinct even when another authorized user has approved and posted it in the meantime. An unseen request is retired without execution; a supported authored invoice is then restored for correction and a new explicit review. Draft quantities and money retain their exact meaning. Entity paging preserves authored party and line fields while invalidating any previous confirmation.

Successful creation refreshes the invoice action picker when its current editor can leave. If another edit blocks refresh, or a read fails after acknowledgement, the invoice remains a known saved draft and no financial retry is offered. A reload that has found a retained command can still offer explicit recovery if entity-choice loading fails. Detaching a controller while confirmation retention completes cannot trigger a late financial execution. Current capability or tool revocation removes unavailable creation controls, including when the user has a dirty form.

All twenty-nine new message keys have entries in the eight current locales. Literal party and line text remains text, including strings that resemble HTML. Locale changes preserve selected IDs, authored values, confirmation and request bodies. Fields, buttons, line groups and the expandable panel use the existing responsive layout. This is code and synthetic-DOM evidence, not actual rendered-browser, screen-reader or installed-device acceptance.
