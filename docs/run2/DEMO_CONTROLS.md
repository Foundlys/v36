# Native demo preparation and recovery

The existing shared Data workspace now has a Demo section. Automotive and E-commerce use the same native engine, current identity, composition, module permissions and retained manifest. The shared workspace and its ZERO panel remain in place. This prepares and loads demo data; it does not establish a fully accepted demo, working live model, finished Finance/commerce action UI or installed application.

Only an explicitly configured isolated demo tenant with encryption and current management authority can reserve a universe. An ordinary workspace receives an unavailable result without profile or reservation details. Existing business data blocks a new seed. Each tenant retains one reservation: the current owner can discover it, while another manager receives no universe ID, request ID, fingerprint, options or progress belonging to that owner.

The controller previews the selected vehicle/product/order/customer counts and history length before start. Changing the counts invalidates that preview and clears confirmation. The start uses the exact returned options, manifest fingerprint and profile revision, an opaque request ID and explicit user confirmation/reason. Acknowledgements are checked against the current tenant, dealer, actor, industry, immutable plan and actual cursor. A malformed or foreign observation cannot start another batch.

After confirmation, the visible page loads sequential bounded native batches. Each next request follows a verified response with actual progress. Pause finishes the current request, then stops. A hidden page or retired workspace stops further scheduling. Network failure, timeout or an unverifiable acknowledgement requires an explicit saved-status read before another continuation. No reload, status read or reconnect resumes writes automatically. A 20-second browser request timeout stops waiting; it never asserts that the server rolled back an uncertain operation.

Recovery uses the server-owned reservation and cursor. A lost start acknowledgement needs no browser-held payload to rediscover the one authorized universe after an encrypted server restart. This is not an arbitrary request search or permission bypass. A new explicit continuation uses the current profile revision and saved cursor; it never repeats an assumed batch length. The underlying native receipts, permissions, dependency checks and durable transaction remain authoritative.

The controls preserve literal form input while switching among all eight existing locales. Product copy distinguishes fictional demo business data from source references and says that the full demo remains in development. Seed progress counts native loading steps, not Run-2 completion or accepted requirements.

Actual encrypted HTTP checks cover unavailable ordinary runtimes, existing-data refusal, lost reservation recovery after restart, owner isolation and role denial. Controller/native-engine checks cover preview invalidation, confirmation, pause, lost start/batch replies, actual-cursor recovery, view retirement, current access loss and locale changes without requests or writes. Minimal DOM checks do not prove mobile layout, keyboard/screen-reader behavior, real browser installation or microphone use; those remain separate acceptance gates.
