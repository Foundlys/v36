# Native and ZERO Finance invoice controls

The Finance page now offers five explicit operations against current authorized invoices: posting, recording an internal payment, creating a full credit draft, allocating a posted credit to its original invoice and recording an internal outgoing credit refund. The same page uses the existing native Finance contracts or structured ZERO actions. This completes a bounded set of invoice controls; it does not complete invoice creation, purchase approval, all Finance controls or the full demos.

The controller lists at most fifty invoices per page, showing the company, counterparty, document number, current status and exact currency amount. Monetary input accepts whole amounts or at most two decimal places without thousands separators, preserving integer cents up to the native safe limit. Preparation displays the current amount and date, with localized blockers. Editing the selected action or its inputs invalidates the review; changing the reason clears confirmation. The current source hash, exact payload and request identity remain bound through the separate confirmation.

Before a financial attempt the normal encrypted server store retains the exact confirmation under the current owner, tenant and dealer. Reload discovers only that owner's unresolved confirmations for currently authorized operations. It never executes a rediscovered command automatically. Explicit recovery observes the original outcome and current invoice separately; an unseen request is durably retired before a delayed original can execute. Confirmed outcome acknowledgement keeps the original retained command while removing it from the unresolved list. Failed retention prevents execution; failed acknowledgement retains recovery. A late retention request cannot reopen an already completed or retired native request. No financial input is stored in browser storage.

The screen preserves the original/current invoice distinction and separately identifies internal registration; it does not claim bank settlement. Current native role, module and operation capabilities govern retention, discovery, execution, recovery and acknowledgement. Native/ZERO transport switching and report refresh preserve dirty or uncertain controls; revoked capabilities remove unavailable operations. Late replies cannot execute from a detached controller.

All 69 new message keys have explicit entries in the eight existing locales. Changing locale reformats presentation without changing selected native IDs, editable values, confirmation, request bodies or literal company/counterparty/source text. The responsive grid, wrapping actions, labelled fields and status announcements are implemented. Actual browser layout, screen-reader behavior and installed iPhone/Android/desktop review remain open.
