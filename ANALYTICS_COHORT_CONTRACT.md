# Observed cohort retention

GET `/api/analysis/cohorts` is a read-only canonical projection. Current Analytics read, reports and events access are required before source retrieval. Existing event ACLs filter the source data first; hidden records contribute neither members, values, evidence nor invalid-record counts. No workflow or report is implicitly saved or executed.

The caller explicitly supplies `acquisition_event`, a different `return_event`, `identity_field` (customer_id, lead_id, anonymous_id or session_id), offset-bearing `from` and exclusive `to`. `interval_days` is 1, 7 or 30; `periods` is 1–12 following intervals. Unsupported filters are rejected. The maximum requested span is 366 days. Query validation precedes source retrieval. The projection selects only the two requested event names, readable under current ACLs and before the observed end, before making detached copies. At most 20,000 selected events and 8 MiB of serialized selected data are accepted; exceeding either limit rejects the whole query. Earlier acquisitions remain eligible for first-retained-acquisition exclusion. The retained array is still scanned linearly; no indexed-query or large-tenant performance acceptance is claimed.

Membership uses each source/identity pair's earliest accessible acquisition event in retained history. Earlier acquisitions exclude that pair from the selected cohort range; this is not proof of the first lifetime acquisition or complete source history. Equal IDs from different sources are not merged. Invalid identities are excluded, event IDs are deduplicated, and only return events at or after the member's acquisition count. No person is inferred from an actor ID.

Fixed-duration intervals are anchored at `from`, independent of local DST. Period zero means return during the acquisition interval. Each cell counts distinct returning cohort members, divided by observed cohort size. The percentage is null until the whole interval is within the observed range, bounded by the requested `to` and current time. Zero is used only for a completed interval with observed members and no matching return. An empty source result has no fabricated cohorts.

Results include definition/version, period bounds, source names, freshness, excluded accessible record counts, source references and explicit truncation above 2,000 references. Provider verification is retained from canonical evidence, not invented. Source completeness, statistical confidence, comparison and trend are not estimated. This is a batch projection, not a realtime stream.

The actual Analytics page has a separate cohort form/table and evidence disclosure; it no longer sends the Cohorts link to generic historical aggregates. Failed requests and revoked capabilities clear the result. Fields and source text use DOM text insertion. Unit and authenticated Analysis-only HTTP tests cover arithmetic, interval edges, private records, revocation, duplicate events and encrypted restart. Browser/keyboard/viewport acceptance remains unproven. Owned saved definitions now persist through the existing Core adapter. Broader analytic models, definition revision history, cohort-specific ZERO tools and browser interaction remain future work.

## Saved definitions

`/api/analysis/cohort_definitions` uses the existing owned record, audit, outbox, idempotent create, compare-and-swap update and retained export contracts. Each definition contains a title, explicit canonical query and model version 1. Only DRAFT and ARCHIVED states are supported. Saving does not retrieve events, save a result or execute a workflow. Definition records follow current owner/administrator visibility, and current Analytics reports write permission is required to save.

`GET /api/analysis/cohort_definitions/:id/query?expected_revision=N` requires the exact current definition revision, rejects archived/unsupported versions and query overrides, and recalculates using the requesting principal's current event/report rights and source ACLs. It returns a definition reference, with `saved_result: false`; it does not reuse the creator's authority or a persisted result. Events capability revocation prevents calculation while reports-only users can still retrieve definitions. Owned export preserves definitions after module disablement.

The actual Analytics form supports named saves, paginated discovery and explicit loading followed by calculation. UTC date/time fields preserve a saved definition's time precision. Editing an input switches to an ad-hoc calculation; unchanged loaded definitions use the revision-bound endpoint. Source completeness is still not inferred from a saved definition. Unit and authenticated HTTP tests cover private owners/sources, create replay, changed-input replay denial, update conflicts, storage rollback, encrypted restart, revocation before source retrieval, archive and retained export.
