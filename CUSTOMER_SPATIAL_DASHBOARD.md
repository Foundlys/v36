# Customer spatial dashboard

Scope: the existing customer start-page visualization, with the existing business modules, tenant resolution, endpoints, authentication and ZERO handlers retained. No new backend capability or permission is introduced.

The scene uses actual CSS 3D world coordinates, a perspective camera, a shared rotating 3D ancestor and camera-facing interactive node surfaces. Connections use 3D endpoint geometry in the same depth context. This is not a rotated image or a flat chart. There are nine deliberately unequal module positions and radii; the initial Z range spans 750 world units. The view makes a continuous 360-degree turn in 180 seconds. Pause stops the world pose immediately; resume continues from that same pose. Manual drag and arrow-key inspection work while paused. Keyboard focus pauses movement.

The only main presentation identities are INKOOP, VERKOOP, FINANCE, CRM, AGENDA, MAIL, SOCIAL MEDIA, MARKETING and ANALYTICS. MAIL uses the existing communication entitlement. SOCIAL MEDIA uses the existing marketing entitlement and campaigns capability; it does not add a new module semantic. Disabled, unauthorized and unentitled modules are omitted. Capabilities come from the existing catalog intersected with current server resolution and accessible workspace navigation. No default customer capabilities are fabricated if loading fails.

Facebook, Instagram and TikTok appear only for their own CONNECTED source-registry entries; a Meta connection alone is insufficient. Other subnodes correspond to actual enabled capabilities. Activation revalidates the current snapshot, then navigates to an existing authorized route/section. Backend gates remain authoritative. General workspace and CRM section deep links select only an existing section; they do not bypass access checks.

The visual layer uses black surfaces, restrained muted module accents, thin depth-bearing connectors and no symbol halos. The central identity reads FOUNDLY / INTELLIGENCE IN MOTION. Resize scales all three axes and camera perspective together, retaining depth and asymmetry; labels compensate for small viewports without equalizing perspective scale.

Targeted reproducible verification: `npm run test:spatial`. It covers 2,560 combinations through the actual resolver, capability flags, tenant mismatch, source lifecycle, navigation destinations, line endpoints, 360-degree geometry, pause/resume, manual and keyboard handling, revoked access, failed loads, actual served assets and production authentication in an isolated HTTP fixture. Existing ZERO client and speech/audio/visual regressions also pass. Fixtures do not prove actual provider or customer acceptance.

The supplied blue and black references are now visually available in the conversation. The blue image determines the irregular composition: Mail high/deep, Marketing upper left, Analytics upper right/deep, Inkoop right/foreground, Verkoop nearer the core, and Agenda/CRM below. Finance occupies a separate low/background position rather than introducing the reference's unrequested Voorraad module. The black image determines the dark shaded circular core, thin outlined icon discs, capsule name labels and discreet colored connections. Reference-only modules, fabricated live statistics, sidebar additions and large symbol halos are not copied because the explicit written scope excludes them.

Visual acceptance remains **UNVERIFIED** for the running implementation. The previously attempted supported cloud-browser preview was rejected with `net::ERR_BLOCKED_BY_CLIENT`; the new reference attachments do not establish that this browser restriction changed. No repeat browser attempt, alternative network route or security bypass was used. Actual rendered occlusion, viewport readability and browser interaction still require visual review. The reference-availability blocker is resolved; the browser-rendering acceptance blocker is not. This implementation is not a visual PASS or an authorization to replace the tested production release.
